# Release checklist

## Nearby discovery and Apple Maps break search — 2026-10-08 (local changes)

**The intended product discovers places automatically wherever usable source data exists. Berlin-Mitte is the deployed beta's temporary data restriction, not the intended product boundary.** The owner selected no additional provider subscription and Apple Maps for iPhone “Find a break”, alongside OSM for tour content. No backend deployment, native build, TestFlight submission or hosted legal update was performed in this work.

- OSM remains the source for the persistent place catalogue, tour stops and downloadable content. The existing Overpass ingestion can be included explicitly with `node scripts/deploy-beta-backend.mjs --include-ingestion`; without `--apply` this only builds/prepares the manifest. Live mode requires a configured endpoint and removal of `TUUR_BETA_SNAPSHOT_TILES` from the beta deployment environment. Previously imported locked Berlin records remain usable.
- `ensureArea` accepts six-character tiles, queues the immediate tile before its neighbors and atomically limits new tile claims per UTC day (3000). The separate Overpass guard allows at most 1500 actual attempts/day (`OVERPASS_DAILY_LIMIT`, raised from 50 in D68) and one request in flight. One cold two-ring neighborhood can require 25 tiles; each tile is fetched once and then served from the shared cache. Successful areas are shared and cached; source failure never becomes a successful empty area.
- The task worker processes one job at a time, uses 120-second minimum retry backoff and skips fresh/locked areas on duplicate delivery. It fetches required OSM data before geocoding/enrichment. Beta queued claims remain protected for two hours. Quota-deferred areas retain a retry deadline; after that deadline, Retry, reopening or movement may be needed once automatic task retries have exhausted.
- Home uses one discovery request owner, does not request Berlin sample data in live mode without a location, retains loaded places during failure/retry and distinguishes source errors from empty results.
- The iPhone break feature uses native Apple MapKit search and a corresponding Apple map. Results are temporary, separate from stored OSM POIs, and must not enter Firebase, AI requests, tour history or offline packs. Directions open Apple Maps and pause the existing tour; failed handoff restores the previous playback state. Android/web retain the OSM break flow. On iPhone, Home also shows a live Apple Maps fallback for museums and culture, only when OSM has no places (empty or failed) for the real position; those places are never stored, merged, narrated or toured (D68). A native rebuild and iPhone acceptance are required for the new local Expo module; an older binary can offer external Apple Maps search instead.

### Source verification and rollout

Private.coffee is a no-subscription candidate: its [service page](https://private.coffee/services.html), [availability terms](https://private.coffee/terms.html), and [OSM instance listing](https://wiki.openstreetmap.org/wiki/Overpass_API#Public_Overpass_API_instances) describe the service and permitted project use. Early small requests returned HTTP 500, then the actual application adapter succeeded on a public Paris/Louvre sample: 50 raw records, 32 app POIs, 30 named accessible candidates, 21 quality POIs. The non-secret local result is `.firebase/osm-nearby-check-20261008.json`. This verifies one upstream query, not deployed Firebase ingestion or worldwide availability.

`node scripts/check-osm-source.mjs --endpoint=https://overpass.private.coffee/api/interpreter` prints a network-free plan. Add `--run` for one bounded request through the real adapter; optional `--output=<new-path>` saves a non-secret report. Empty, inaccessible-only, partial or failed responses do not pass.

Before activating live beta discovery:

1. Recheck the configured source with the smoke command and retain the result. In the isolated beta deployment environment, set `OVERPASS_ENDPOINT` to that verified source and remove `TUUR_BETA_SNAPSHOT_TILES`; retain existing live provider selections and dedicated identities.
2. Deploy the worker first: `node scripts/deploy-beta-backend.mjs --include-ingestion --functions=ingestArea --apply`. This enables the required Cloud Tasks API and deploys the authenticated serial worker/queue.
3. Run `node scripts/configure-beta-ingestion.mjs` to inspect the narrow queue/self-identity permissions, then `--apply`. The helper verifies the beta project and worker, preserves existing IAM bindings/etags and grants enqueue access on this queue plus permission for the core identity to use itself in task authentication. [Firebase task setup](https://firebase.google.com/docs/functions/task-functions).
4. Deploy the request and navigation endpoints from that environment: `node scripts/deploy-beta-backend.mjs --include-ingestion --functions=ensureArea,getWalkingRoute --apply`. Both previously enforced the Berlin snapshot boundary. Then verify an authenticated/App Check request outside Berlin, actual task delivery, stored real POIs and walking directions.
5. Build and test the native Apple break module on iPhone (search categories, empty/error/retry, map attribution, dismissal/cancellation, external directions and tour pause/resume), publish the matching privacy text, and only then distribute that native build.

Apple is suitable for immediate break/place search, but is not a drop-in source for the persistent OSM catalogue: [Apple Maps terms, Attachment 6 §§2.2–2.5](https://developer.apple.com/support/terms/apple-developer-program-license-agreement/) require corresponding Apple-map display, restrict derived databases and allow only limited temporary storage. Apple Maps Server API/MapKit JS's shared daily allowance is separate from this native MapKit integration; no server Maps key or new provider account was created.

### Updating the preview (PowerShell)

Run from `apps/mobile`; these variables apply only to this preview export. The app needs no production credentials for this route. The `preview` alias is updated without promoting the deployment to production.

```powershell
$env:EXPO_PUBLIC_BACKEND = 'demo'
$env:EXPO_PUBLIC_PAYWALL = 'off'
$env:EXPO_PUBLIC_USE_EMULATORS = 'false'
$env:EXPO_NO_DOTENV = '1'
npx --no-install expo export --platform web
if ($LASTEXITCODE -ne 0) { throw 'Preview export failed' }
npx eas-cli@latest deploy --environment preview --alias preview --export-dir dist --non-interactive --no-source-maps
```
